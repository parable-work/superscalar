# SuperScalar docs site

Source for https://parable-work.github.io/superscalar/. Built with
[Starlight](https://starlight.astro.build/) on Astro; versions are pinned
exactly in `package.json`. The site is deployed by the `docs-deploy` job of
`.github/workflows/release.yml` on every `vX.Y.Z` tag.

## Local development

Node 22.12 or newer (CI uses the `NODE_VERSION` pin in `tools.env`).

```
cd docs
npm install
npm run dev       # http://localhost:4321/superscalar/
npm run build     # writes docs/dist/
npm run preview   # serves docs/dist/
```

`npm run build` fails on a broken internal link (the
`starlight-links-validator` plugin) and on a sidebar entry that points at a
page that does not exist. Fix the page rather than the validator.

## Layout

```
docs/
  astro.config.mjs        site URL, base path, sidebar groups, edit links
  src/content.config.ts   Starlight content collection
  src/content/docs/       one Markdown file per page
    index.md              overview
    install/              per-language install and quickstart
    concepts/             registry, scalar kinds, comparability and sortability
    guides/               add a built-in scalar, build an extension, conformance
    policy/               ABI and versioning, security
    reference/            generated per-scalar pages (see below)
    faq.md
    404.md                not-found page, emitted as dist/404.html for GitHub Pages
  src/content/i18n/en.json  empty UI-string overrides; keeps the i18n collection non-empty
```

Links inside pages are written with the `/superscalar/` base included, for
example `/superscalar/install/rust/`, because the site is served under that
path on GitHub Pages.

## The reference section is generated

`src/content/docs/reference/` holds one page per scalar produced by
`superscalar docs` from the registry and the conformance vectors. CI runs the
generator into that directory before `npm run build`; the directory is
gitignored apart from `index.md`, so a local build without the generator shows
only the index page. To see the full reference locally, run the generator
(`superscalar docs`, the `docs` subcommand of the `superscalar-codegen`
crate's CLI) into that directory first; the subcommand's flags are documented
by the CLI itself.

Do not hand-edit generated pages; change the registry entry or the vectors and
regenerate. `superscalar docs --check` fails when a scalar has no vectors or no
description, and CI runs it.

## Writing pages

Plain ASCII, sentence-case headings, no em dashes. Every page starts with a
frontmatter block carrying `title`, `description` and `sidebar.order`; the
sidebar groups are autogenerated from the directory names in
`astro.config.mjs`.
